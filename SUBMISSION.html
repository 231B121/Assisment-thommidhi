Brief Summary

Invariant Maintained

The validator enforces a conservation invariant across all input batches: $$\text{len}(\text{valid_entries}) + \sum \text{failure_counts.values()} = \text{len}(\text{raw_outputs})$$ Each invalid string is attributed to its earliest validation failure in the pipeline, ensuring predictable logging and telemetry.

Edge Cases That Break Naive Implementations

  1. The Python Boolean Subclass Trap (probability: true):
  2. Why Naive Fails: In Python, bool is a subclass of int (issubclass(bool, int) == True, and isinstance(True, int) == True). Naive validators checking isinstance(val, (int, float)) and 0.0 <= val <= 1.0 evaluate 0.0 <= True <= 1.0 as True. Consequently, raw JSON containing "probability": true is incorrectly admitted as valid.

  3. Our Fix: Explicitly disallow booleans: if isinstance(prob, bool) or not isinstance(prob, (int, float)): record_failure("invalid_probability_type").

  4. Non-Object JSON Roots ([...], null, "string", 123):

  5. Why Naive Fails: Standard json.loads happily parses JSON arrays ([{"title": ...}]), null literals (null), and primitives. Naive implementations immediately call data.keys(), throwing AttributeError: 'list' object has no attribute 'keys' or AttributeError: 'NoneType' object has no attribute 'keys' and crashing the process.

  6. Our Fix: Enforce if not isinstance(parsed, dict): record_failure("not_a_json_object").

  7. Non-String Field Values with Misleading Lengths:

  8. Why Naive Fails: If a model produces "reason": 12345, naive code doing len(data["reason"]) > 200 crashes with TypeError: object of type 'int' has no len(). If "reason": ["one", "two"], naive code evaluates len(list) <= 200 as valid despite failing the type contract.

  9. Our Fix: Explicitly verify isinstance(parsed["reason"], str) before checking length.

  10. Floating Point Non-Numbers (NaN, Infinity):

  11. Why Naive Fails: Standard Python json.loads parses "probability": NaN or Infinity into float('nan') or float('inf'). Comparisons like 0.0 <= float('nan') <= 1.0 produce False, but downstream math or database operations fail silently.
  12. Our Fix: Explicit check via math.isnan(prob) or math.isinf(prob).

Test Suite Summary

The test suite in validate_outputs.py includes 11 automated test cases: - test_01_valid_standard: Nominal valid JSON. - test_02_valid_boundary_values: Boundary checks ($0.0$, $1.0$, reason exactly 200 characters). - test_03_naive_breaker_boolean_probability: Rejection of JSON true in probability. - test_04_naive_breaker_json_array_root: Graceful handling of JSON array root without crashing. - test_05_naive_breaker_non_string_reason_type: Rejection of integer/list reason without TypeError. - test_06_naive_breaker_json_null_root: Graceful handling of null root without AttributeError. - test_07_invalid_syntax_json_decode_error: Rejection of malformed syntax (unclosed braces). - test_08_invalid_keys_missing_or_extra: Rejection of missing reason or extraneous score. - test_09_probability_out_of_range: Rejection of values $< 0.0$ or $> 1.0$. - test_10_reason_too_long_201_characters: Rejection of reasons exceeding 200 characters. - test_11_batch_invariant: End-to-end verification that valid count + failure count equals batch size.

Core Decisions & Trade-offs

  1. Single-Hop Multilingual vs Two-Stage Translation:
  2. Rejected Alternative: "Detect Tenglish $\to$ Translate to English $\to$ Run English LLM $\to$ Translate back to Tenglish".
  3. Why rejected: Adds 2 extra network hops, inflates latency by $+1.5\text{s}$ to $2.2\text{s}$ (breaching the 3s SLA), triples token spend, and strips vernacular warmth into stiff formal Telugu script.

  4. Selected Design: Native single-hop processing. Gemini Flash and Llama 3.1 have high zero-shot Romanized Indic capability. A system prompt with two Tenglish few-shot examples anchors the response in natural, conversational Telugu/Tenglish without translation overhead.

  5. Server-Sent Events (SSE) Streaming vs Buffered JSON:

  6. Trade-off: We trade strict JSON schema buffering for markdown streaming. Buffering a full response forces the user to stare at a spinner for 1.2s; streaming delivers the first visual token in $< 400\text{ms}$, reducing perceived latency by 70%.

Part 3. Keeping a Model Honest: Eliminating Fabricated Numbers

The Problem

When asked which video title will get more clicks, language models frequently hallucinate pseudo-precise statistics:

"Title A will get 64.3% more clicks because it has a stronger psychological curiosity gap."

The model possesses zero empirical data regarding real-world viewer behavior, impressions, thumbnail pairing, or algorithmic distribution. This stems from pseudo-precision bias: autoregressive models emulate the authoritative tone of marketing blogs and sales copy that invent statistics to sound persuasive.

  1. Schema Design & Output Parameterization:
  2. If using structured outputs (Function Calling / JSON mode), strictly exclude numeric probability or percentage fields from the schema.
  3. Constrain the output schema to qualitative dimensions: json { "recommended_title": "string", "heuristic_category": "Curiosity Gap | Keyword Prominence | Mobile Length", "qualitative_reasons": ["string"], "suggested_ab_test": "string" }

  4. Constrained decoding physically prevents the model from populating a numeric prediction field.

  5. Epistemic System Prompt Contract: text You are an editorial copywriting advisor. STRICT CONSTRAINT: You do NOT have access to YouTube telemetry, audience demographics, or empirical click data. If asked for numbers, explain that empirical performance can only be measured via real-world A/B testing in YouTube Studio.

  6. Few-Shot Negative Demonstrations (Contrastive In-Context Calibration): Include explicit demonstrations of rejected vs. accepted responses:

  7. Negative Demonstration: "Title 1 will get 40% higher CTR." $\to$ Flagged as hallucination.
  8. Corrected Demonstration: "Title 1 front-loads the keyword, which helps search discovery, but exact CTR can only be verified using YouTube's Test & Compare feature."

Downstream Interception: Catching It Automatically in Production

Even with strong prompting, stochastic models occasionally hallucinate numbers. We employ a three-tier automated safety net:

Tier 1: Real-Time Deterministic Interceptor ($< 5\text{ms}$)

A fast regex and entity scanner inspects generated tokens before they reach the user:

import re

FABRICATED_NUMERIC_PATTERN = re.compile(
    r"(?i)\b("
    r"\d+(\.\d+)?%\s*(more|higher|increase|boost|uplift|better|clicks|views|CTR)"
    r"|(probability|likelihood|chance)\s*(of\s*)?(is\s*)?\d+(\.\d+)?%?"
    r"|\b\d{1,2}\s*out of\s*10\s*viewers\b"
    r")\b"
)

def inspect_response(text: str) -> str:
    if FABRICATED_NUMERIC_PATTERN.search(text):
        # Redact fabricated claims and append calibrated disclaimer
        sanitized = FABRICATED_NUMERIC_PATTERN.sub("[Empirical claim redacted]", text)
        return (
            sanitized + "\n\n*(Note: Exact CTR percentages cannot be predicted prior "
            "to publication. Run YouTube's 'Test & Compare' feature for real viewer data.)*"
        )
    return text
  • If a fabricated percentage is detected during streaming, the chunk is intercepted and replaced with qualitative advice.

Tier 2: Asynchronous Offline LLM-as-a-Judge (Shadow Audit)

  • 100% of flagged responses and a random 10% sample of all production queries are routed to an offline audit queue.
  • An evaluator prompt audits whether the response made ungrounded empirical claims: $$\text{ungrounded_claim} \in {\text{True}, \text{False}}$$

Tier 3: Production Metrics & CI/CD Gating

  • Core Production Metric: Unsubstantiated Quantitative Claim Rate (UQCR): $$\text{UQCR} = \frac{\text{Responses with ungrounded numeric claims}}{\text{Total production responses}} \times 100$$
  • Alerting Threshold: PagerDuty/Slack alert if $\text{UQCR} > 0.05\%$ over a 15-minute rolling window.
  • CI/CD Regression Suite: Run 150 adversarial test cases (e.g. "Give me the exact percentage chance Title A wins") against any proposed prompt or model change. The deployment pipeline fails if any run yields $\text{UQCR} > 0\%$.
